# 资产管理与物联网平台需求规格

> 状态：V1.0 需求基线  
> 更新日期：2026-08-11  
> 说明：本文固化当前已确认范围。标记为“待确认”的内容不会在实现中自行假定。

## 1. 产品目标

建设一套面向多租户、多项目的资产管理与物联网 SaaS 平台，完整重做前端、后端、数据库、实时服务和 MQTT 设备接入。管理端以 Art Design Pro 为基础，重新组织信息架构和交互，不要求复刻参考系统的页面布局。

平台需要同时解决：

- 资产、网关、信标、地图、区域、定位、告警和盘点的日常管理。
- 设备通过 MQTT 上报真实数据，并由后台完成解析、存储、状态更新、告警、定位和实时推送。
- Root、多个平台超级管理员、租户管理员、项目角色、自定义角色，以及跨租户/多项目成员关系。
- 项目任务、成员和文档不再使用占位页面，而是提供真实可用的业务能力。
- 中英文切换及关键操作全链路审计。

## 2. 已确认的产品决策

| 事项 | 决策 |
| --- | --- |
| 建设范围 | 前端、后端、数据库、实时服务全部重做 |
| 管理端 | Art Design Pro，按新的合理布局重构 |
| 架构 | 模块化单体 API + 可独立部署和扩容的 MQTT Worker |
| 数据库 | PostgreSQL + PostGIS |
| 缓存与短期事件流 | Redis；Redis 不是业务事实数据的唯一存储 |
| MQTT Broker | 仅采用开源方案；开发环境使用 Mosquitto |
| MQTT 能力 | 接入真实设备信息，不只做配置页或连接测试 |
| Broker 管理 | 支持多 Broker、环境区分、主备配置和项目授权 |
| 权限 | 不可删除 Root、多个超级管理员、完整 RBAC、自定义角色 |
| SaaS 租户 | 平台、租户、项目三级作用域；租户是客户组织边界，项目不能代替租户 |
| 多项目 | 一个用户可属于多个项目，并在不同项目拥有不同角色 |
| 项目删除 | 默认归档，可恢复；不直接物理删除 |
| 注册 | 生产环境关闭公开自助注册，采用管理员邀请或审核 |
| 国际化 | 中文、英文 |
| 项目协作 | 本期实现任务、成员、文档 |

## 3. 用户与角色

### 3.1 平台级角色

- **Root**：系统引导阶段创建的最高权限账号。不可在普通管理界面删除、停用或降级，用于管理超级管理员和平台安全配置。
- **超级管理员**：按平台角色管理租户、全局用户、全局设备类型、Broker、平台参数和审计信息，但不能越权修改 Root。

### 3.2 租户级角色

- **租户所有者/管理员**：管理所属客户组织的资料、成员、租户角色、项目、配额和租户级配置，不能查看其他租户。
- **租户成员**：可以属于一个或多个租户；在每个租户中的角色和有效期相互独立。
- **自定义租户角色**：由租户管理员在可委派边界内组合租户级权限，不能授予平台权限。

### 3.3 项目级角色

- **项目管理员**：管理指定项目内的成员、角色、业务配置和业务数据。
- **项目成员**：按被分配的一个或多个项目角色访问功能。
- **自定义角色**：由授权管理员组合菜单、按钮、API 和数据范围权限。角色只在其所属范围内生效。

平台、租户与项目角色相互独立。同一用户可以是租户 A 的管理员、租户 B 的普通成员，也可以在各租户的不同项目中拥有不同角色。项目必须且只能属于一个租户。

## 4. 功能范围

### 4.1 认证与账户

- 用户名或已验证邮箱登录、退出、刷新会话。
- 管理员邀请用户；按平台策略审核申请或邀请结果。
- 忘记密码、重置密码、修改密码、首次登录改密。
- 账户启用、停用、锁定、解锁和有效期控制。
- 个人头像、昵称、手机、邮箱、语言和基础偏好设置。
- 登录失败限制、会话撤销和安全事件审计。
- Access Token 使用短有效期；刷新凭证不得暴露给普通脚本存储。

### 4.2 租户、项目与成员

- 租户创建、编辑、启停、归档、恢复、配额和基础配置。
- 租户成员邀请、审核、停用、移除及租户角色分配。
- 用户可加入多个租户，并在租户间安全切换上下文。

- 项目创建、编辑、启停、归档、恢复、筛选和分页。
- 项目资料、标识、时区、默认语言及业务参数。
- 指定和调整项目管理员。
- 用户在所选租户内加入多个项目；按“租户 → 项目”顺序安全切换当前上下文。
- 邀请、移除、停用项目成员，分配一个或多个项目角色。
- 归档项目默认只读，恢复后才能继续产生业务写入。

### 4.3 权限管理

- 平台角色、项目角色和自定义角色管理。
- 菜单、页面、按钮、API 操作和数据范围权限。
- 后端作为最终授权边界；隐藏前端菜单不能代替后端鉴权。
- 防止越权授予权限、跨项目访问和通过修改请求参数绕过权限。
- 权限、角色、成员关系和管理员变更进入审计日志。

详细模型见 [rbac.md](./rbac.md)。

### 4.4 工作台与统计

- 资产、网关、信标、未处理告警等核心指标。
- 在线状态、温度趋势、步数排行和实时告警。
- 资产类型、区域、信标电量、网关状态等分布。
- 告警分类、处理率和趋势。
- 盘点在线率和结果统计。
- 日期范围、项目范围、刷新、自动刷新和全屏。
- 所有图表必须来自真实接口；禁止使用伪造数据掩盖接口错误。

### 4.5 资产中心

- 资产新增、编辑、查询、归档、批量操作和导入导出。
- 资产编码、名称、类型、扩展属性和业务状态。
- 资产类型管理。
- 绑定、换绑和解绑信标，并保留绑定历史。
- 资产当前状态：在线、电量、温度、步数、最后心跳、所在区域和位置等。
- 资产状态历史、趋势和详情。
- 导入任务需要提供校验预览、错误明细和可重试结果，不允许静默丢行。

### 4.6 网关、信标与设备类型

- 网关增删改查、批量操作、导入导出、状态和详情。
- 网关标识、MAC、类型、固件、网络、地图坐标和覆盖参数。
- 信标增删改查、批量操作、导入导出、状态和扫描历史。
- 信标标识、MAC、类型、电压、温湿度、运动和按键等数据。
- 全局网关类型、信标类型及项目可用范围管理。
- 设备参数解析配置支持版本化、校验和回滚。
- 删除采用引用检查或归档，不能造成历史记录失去关联。

### 4.7 地图、区域与定位

- 地图上传、更换、归档、尺寸信息和两点距离校准。
- 地图缩放、平移、旋转及坐标换算。
- 在地图上配置网关坐标和覆盖范围。
- 绘制、编辑和校验区域多边形。
- 实时展示地图、区域、网关、资产及其状态。
- 资产定位详情、定位时间、精度、来源和参与网关信息。
- 按资产、地图和时间范围查询历史轨迹，并支持播放和倍速。
- 定位算法和参数可配置、可观测；具体算法与精度验收标准待设备样例和现场条件确认。

### 4.8 告警中心

- 资产、网关、信标离线以及电压、温度、运动、按键等告警。
- 告警规则的启停、阈值、持续时间、冷却时间、严重级别和适用范围。
- 告警产生、确认、分派、处理、关闭和备注。
- 单条与批量操作、筛选、统计和导出。
- 告警去重、抑制、恢复事件和处理时效记录。
- 告警规则版本及变更审计。
- 通知渠道不在当前已确认范围内；如需短信、邮件或企业消息，另行确认。

### 4.9 资产盘点

- 创建盘点任务，选择资产或范围并设置起止时间。
- 开始、停止、取消和查看实时进度。
- 在线、离线、已发现、未发现和异常结果。
- 盘点详情、历史记录、结果导出和审计。
- 并发盘点冲突规则由后台统一校验。

### 4.10 项目协作

#### 任务

- 项目内任务的创建、编辑、指派、状态、优先级、截止时间和归档。
- 任务列表、筛选、详情、评论和操作记录。
- 任务只可指派给当前项目有效成员。

#### 成员

- 项目成员邀请、审核、角色分配、状态管理和移除。
- 展示成员所属角色、加入时间和最近活动等必要信息。

#### 文档

- 项目内目录、文件上传、下载、重命名、移动、归档和版本替换。
- 文件权限继承项目权限，并记录下载、替换、归档等审计事件。
- V1 不包含多人在线协同编辑；可通过上传新版本完成版本管理。

### 4.11 MQTT 与真实设备接入

- 多 Broker 配置，区分开发、测试和生产环境。
- Broker 连接测试、启停、运行状态、重连次数和错误原因。
- MQTT 3.1.1/5.0，以及 MQTT、MQTTS、WS、WSS（是否启用由 Broker 能力决定）。
- 用户名密码、TLS/mTLS 证书和密钥的加密存储与前端脱敏。
- Broker 与项目授权、Topic 路由、设备身份映射和解析规则版本。
- 接收真实设备数据，保存必要的原始报文和标准化事件。
- 驱动资产状态、定位、告警、盘点、统计和 WebSocket 实时推送。
- 支持下行命令、应答和超时模型；是否开放具体设备控制以用户提供的协议为准。
- 至少一次处理语义、幂等去重、失败隔离、重试和可追踪性。

不得臆造 Topic、字段、单位或设备命令。协议约束和待提供资料见 [mqtt-protocol.md](./mqtt-protocol.md)。

### 4.12 系统管理与审计

- 用户、平台角色、项目角色、项目和系统参数管理。
- Broker、全局设备类型、解析规则和文件存储配置管理。
- 登录、账户、权限、项目、MQTT 配置、设备命令和关键业务操作审计。
- 审计记录包含操作者、作用范围、动作、目标、结果、时间、来源及必要的变更摘要。
- 敏感字段不得进入普通日志、审计详情或导出文件。

### 4.13 国际化与文件能力

- 前端菜单、表单、校验、状态、错误提示和后端业务消息支持中英文。
- 时间存储使用 UTC，按用户或项目时区展示。
- 地图、头像、项目文档和导入文件使用 S3/OSS 兼容对象存储接口。
- 导入导出任务对大文件采用异步处理，并提供进度和结果。

## 5. 非功能要求

### 5.1 安全

- 所有业务 API 均需认证和后端授权，公开接口采用明确白名单。
- 项目业务表必须带项目归属；跨项目查询默认拒绝。
- PostgreSQL 行级安全可作为项目隔离的第二道防线。
- 密码使用业界认可的自适应哈希；密钥、Broker 密码和证书加密存储。
- 防范越权、注入、XSS、CSRF、暴力登录、恶意文件和大报文攻击。
- 生产环境强制 TLS，不在浏览器中直接连接 MQTT 或暴露 Broker 凭据。

### 5.2 可靠性

- PostgreSQL 是业务事实数据的最终来源；清空 Redis 不得丢失资产、告警、轨迹、盘点或命令历史。
- MQTT QoS 1 场景按“可能重复、可能乱序”设计。
- 消费、任务和命令均有明确状态、重试上限和失败记录。
- Worker 重启、Broker 断连和 WebSocket 断连后能够恢复。
- 归档、审计和数据迁移操作必须可追踪。

### 5.3 可维护性

- API、MQTT Worker 和领域模块边界清晰；禁止跨模块直接依赖内部实现。
- 数据库变更使用版本化迁移。
- OpenAPI、关键领域规则和运维步骤保持同步。
- 核心授权、幂等、告警和定位流程具备自动化测试。

### 5.4 可观测性

- API、Worker、Broker 连接、消息吞吐、处理延迟、失败率、积压量和 WebSocket 连接可监控。
- 日志包含请求或消息关联标识，但不记录凭据和完整敏感报文。
- 健康检查区分“进程存活”和“可对外服务”。

### 5.5 性能与容量

最终吞吐、延迟、保留期和可用性指标需依据设备数量、上报频率、峰值消息量和部署资源确定。在这些输入确认前，不写入虚假的性能承诺；首个真实 MQTT 垂直切片必须包含基准测试和容量报告。

## 6. 明确不做

- 不按参考网站做像素级复制，也不复制其假数据、占位功能和已知安全问题。
- 不采用商业 MQTT Broker 或依赖商业集群特性。
- 首期不引入 Kafka、Kubernetes 或拆分大量微服务；达到明确容量或组织边界后再评估。
- 浏览器不直接持有 Broker 密码或直接订阅设备 Topic。
- 生产环境不开放匿名自助注册。
- 项目不从常规管理界面直接物理删除。
- V1 不提供多人在线协同编辑文档。
- 未获得协议样例前，不实现或伪造具体 Topic、字段映射、定位精度或设备控制命令。

## 7. 待用户提供或确认

1. 设备、网关、信标预计数量，上报间隔和峰值消息速率。
2. 实际 Broker 类型、部署拓扑、认证方式和 TLS 要求。
3. 上行 Topic、真实报文、字段含义、单位、时间戳、序列号和 QoS。
4. 如需控制设备：下行 Topic、命令、ACK、超时、重试和幂等规则。
5. 原始报文、状态、轨迹、告警、盘点和审计记录的保留期限。
6. 定位算法输入、坐标系、地图标定方式和可接受精度。
7. 告警阈值、恢复规则、通知渠道和升级策略。
8. 是否迁移旧系统数据，以及可提供的数据字典和导出样本。
9. 生产部署规模、可用性目标、备份恢复目标和对象存储选型。

## 8. 验收原则

- 每项功能必须以真实后端接口和持久化数据闭环验收。
- 权限需同时覆盖正向访问、无权限拒绝、跨项目拒绝和越权授予拒绝。
- MQTT 需使用用户提供的真实样例完成接入、重复消息、乱序、断线重连和错误报文测试。
- Redis 清空或重启后，核心历史数据保持完整，缓存和实时状态可恢复。
- 中文和英文界面均不得出现关键业务硬编码或缺失翻译。
- 所有关键变更可在审计日志中定位到操作者、目标和结果。
