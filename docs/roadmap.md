# 分阶段实施路线

> 本路线按可验收的纵向能力组织，不按页面数量计算进度。  
> 在团队规模、设备流量和真实 MQTT 协议确认前，不给出缺乏依据的工期承诺。

## 1. 实施原则

- 每个阶段都交付前端、API、数据库、权限、测试和运维闭环。
- 优先打通一个真实设备的端到端链路，再扩展大量设备类型和报表。
- 数据库迁移、审计、国际化和权限不是收尾工作，应随功能一起完成。
- MQTT Topic 和字段不得靠猜测；协议样例缺失不阻塞通用骨架，但会阻塞真实接入验收。
- 核心历史以 PostgreSQL 为准，Redis 故障测试从第一条设备链路开始。
- 每阶段通过退出条件后再扩大范围，减少大批页面同时“完成 80%”。

## 2. 阶段总览

```mermaid
flowchart LR
    P0["阶段 0：需求与协议基线"] --> P1["阶段 1：工程基础"]
    P1 --> P2["阶段 2：身份、租户、项目与 RBAC"]
    P2 --> P3["阶段 3：资产与设备主数据"]
    P3 --> P4["阶段 4：真实 MQTT 纵向链路"]
    P4 --> P5["阶段 5：地图、定位、告警与盘点"]
    P2 --> P6["阶段 6：任务、成员与文档"]
    P5 --> P7["阶段 7：看板、导入导出与体验完善"]
    P6 --> P7
    P7 --> P8["阶段 8：安全、容量、迁移与上线"]
```

阶段 6 可在阶段 4/5 进行时并行开发，但共享的项目、权限、审计和文件能力必须先稳定。

## 3. 阶段 0：需求、交互与协议基线

### 目标

把已确认需求转成可测试边界，并收集决定设备接入和容量的真实输入。

### 交付物

- 需求范围、角色和不做事项确认。
- 管理端菜单、关键页面流程和响应式布局草图。
- 权限目录初稿和角色矩阵。
- 核心数据词汇表及实体关系草案。
- MQTT 资料收集模板、真实样例包和字段字典。
- 设备数量、上报频率、峰值、保留期和生产可用性目标。
- 旧系统数据是否迁移的决策。

### 退出条件

- Root、超级管理员、租户管理员、项目管理员，以及多租户/多项目成员流程获得确认。
- 至少一种目标设备有完整上行 Topic、样例、身份和字段说明。
- 如需下行，至少一种命令与 ACK 规则完整。
- 未决事项有负责人和决策时间，不以默认猜测替代。

通用工程建设可与本阶段并行；真实解析实现不能越过协议门禁。

## 4. 阶段 1：工程与运行基础

### 目标

建立可以持续开发、测试和部署的最小工程。

### 交付物

- `web/`：Art Design Pro 基线、环境配置、路由框架、基础布局和中英文框架。
- `server/`：Maven 多模块、API、共享核心和 MQTT Worker 可启动骨架。
- `infra/`：本地 PostgreSQL/PostGIS、Redis、Mosquitto。
- Flyway 基线、统一错误模型、请求关联 ID、OpenAPI。
- 健康检查、结构化日志、基础指标。
- 单元、集成和端到端测试入口。
- 配置分层、密钥注入规则和不提交真实凭据的检查。
- 持续集成至少执行格式、静态检查、编译和测试。

### 退出条件

- 新开发者可按 README 启动基础设施、API、Worker 和 Web。
- API 与 Worker 能访问 PostgreSQL/Redis；Worker 能对本地 Broker 做受控健康验证。
- 数据库可从空库完整迁移。
- 中英文切换、统一错误和健康状态有最小演示。
- 版本库不包含真实密码、私钥或生产地址。

## 5. 阶段 2：身份、租户、项目、RBAC 与审计

### 目标

先建立所有业务模块共同依赖的安全边界。

### 交付物

- Root 引导创建和受控恢复策略。
- 登录、退出、刷新会话、改密、重置、锁定和会话撤销。
- 用户邀请/审核、启停和有效期。
- 租户创建、编辑、启停、归档、恢复和租户切换。
- 租户成员、租户角色和租户管理员管理。
- 租户内项目创建、编辑、启停、归档、恢复和项目切换。
- 多租户/多项目成员关系和项目管理员管理。
- 平台角色、租户角色、项目角色、自定义角色、权限目录和数据范围。
- 动态菜单和按钮展示，以及每个 API 的后端鉴权。
- 授权版本、Redis 权限缓存和可靠失效。
- 关键安全/管理操作审计。
- 租户/项目双层隔离与防提权自动化测试。

### 退出条件

- 同一用户在两个租户及多个项目拥有不同角色时得到对应菜单和 API 结果。
- 修改 URL、批量 ID、导出任务和 WebSocket 目的地不能跨租户或项目。
- Root 不可在管理页面被删除、停用或降级。
- 项目管理员不能授予平台权限或移除最后一名项目管理员。
- 角色变化后旧权限不会持续有效。
- 关键操作能在审计记录中定位操作者、目标和结果。

## 6. 阶段 3：资产与设备主数据

### 目标

建立 MQTT、定位、告警和盘点共同依赖的可靠主数据。

### 交付物

- 资产、资产类型、扩展属性、归档和查询。
- 网关、信标、全局设备类型和项目授权。
- 资产与信标绑定、换绑、解绑和完整历史。
- 地图关联、网关坐标及基础设备状态字段。
- 批量导入的上传、校验预览、错误报告和执行结果。
- 导出任务及有权限、有限时的下载。
- 操作审计、引用检查和数据完整性约束。

### 退出条件

- 资产、网关和信标编码在租户/项目边界内正确唯一。
- 所有绑定变化可追溯且不会破坏历史。
- 导入错误不会静默丢行，重复执行具有明确结果。
- 租户 A 无法读取、修改或导出租户 B 的任何主数据；同一租户内项目仍相互隔离。
- 全局设备类型授权和项目内使用边界清楚。

## 7. 阶段 4：真实 MQTT 纵向链路

### 目标

用至少一种真实设备协议打通“设备 → Broker → Worker → 数据库 → 业务状态 → 页面”的完整链路。

### 交付物

- 多 Broker、端点、环境、租户/项目授权和脱敏凭据管理。
- Worker 连接生命周期、租约、重连和主备框架。
- Topic 路由、协议草稿/测试/发布/回滚。
- 真实协议解析器及自动契约测试。
- Inbox 幂等、原始消息、标准事件、错误隔离和处理追踪。
- 资产/设备当前状态更新和必要历史。
- Redis 实时分发与 WebSocket 租户/项目隔离。
- 连接、吞吐、延迟、重复、错误和积压指标。
- 若协议已提供：下行命令、Outbox、发布、ACK、超时和审计。

### 退出条件

- 用户提供的正常和异常样例均有固定测试结果。
- 重复和乱序消息不会重复产生业务结果或用旧状态覆盖新状态。
- Worker 在数据库提交前后分别崩溃时可恢复且结果正确。
- Broker 断连重连后恢复订阅；主备测试不会造成不可恢复数据丢失。
- Redis 重启不会丢失核心历史，页面能重新同步状态。
- 下行页面不把 Broker PUBACK 显示成设备执行成功。
- 形成基于真实消息规模的首份容量报告。

## 8. 阶段 5：地图、定位、告警与盘点

### 目标

把设备数据转化为可操作的资产位置和业务事件。

### 交付物

#### 地图与定位

- 地图上传、版本、尺寸和两点距离校准。
- 网关点位、覆盖范围、区域多边形及 PostGIS 查询。
- 实时位置、精度、来源、参与网关和最后更新时间。
- 历史轨迹查询、播放、倍速和时间筛选。
- 定位参数版本、异常输入和延迟消息处理。

#### 告警

- 规则、阈值、持续时间、冷却、严重级别和适用范围。
- 产生、去重、恢复、确认、分派、处理和关闭。
- 批量操作、统计、导出和规则变更审计。

#### 盘点

- 范围和时长设置，开始、停止、取消和冲突校验。
- 实时进度、在线/离线/异常结果、历史和导出。
- 设备迟到、重复和盘点边界时间的处理规则。

### 退出条件

- 地图坐标换算和区域包含判断有可重复测试。
- 真实现场样例达到已确认的定位精度和刷新要求。
- 同一异常在冷却窗口内不会形成告警风暴，恢复事件正确。
- 盘点结果在重复、迟到消息下仍一致。
- 地图、位置、告警和盘点均执行项目与动作权限。

## 9. 阶段 6：项目任务、成员与文档

### 目标

补全参考系统中的占位功能，形成可用的项目协作闭环。

### 交付物

- 任务创建、编辑、指派、状态、优先级、截止时间和归档。
- 任务筛选、详情、评论和操作记录。
- 成员邀请、审核、角色分配、状态和移除界面。
- 文档目录、上传、下载、重命名、移动、版本替换和归档。
- 对象存储适配、短时下载授权和文件元数据。
- 任务、成员、评论和文档的项目隔离、权限和审计。

### 退出条件

- 任务只能指派给当前项目的有效成员。
- 被移除成员不能继续访问旧链接、文件或 WebSocket 更新。
- 文档新版本保留历史元数据，归档不会破坏引用。
- 无下载或导出权限的用户不能猜测对象键获取文件。
- 本阶段不使用“开发中”占位代替业务接口。

## 10. 阶段 7：看板、分析与产品完善

### 目标

在真实数据链路稳定后完成管理体验和统计能力。

### 交付物

- 资产、网关、信标、告警和盘点核心指标。
- 在线、电量、温度、步数、类型、区域和告警趋势。
- 时间、项目和资源范围筛选，刷新、自动刷新和全屏。
- 报表查询优化、聚合表或物化视图（以性能数据决定）。
- 所有模块中英文文案、错误、校验、状态和导出列。
- 空状态、加载、错误恢复、权限拒绝和归档状态体验。
- 可访问性和主流桌面浏览器回归。

### 退出条件

- 图表全部来自可追溯真实数据，接口失败时展示错误而非假数据。
- 聚合结果可与明细抽样核对。
- 大范围查询和导出不会阻塞交互请求。
- 中文、英文均通过关键路径端到端测试。
- 页面菜单、路由、按钮和 API 权限一致。

## 11. 阶段 8：安全、容量、迁移与上线

### 目标

把可用产品转为可运营的生产系统。

### 交付物

- 安全威胁建模、依赖和镜像扫描、渗透测试及整改。
- Root/超级管理员强认证和恢复演练。
- 基于真实规模的 API、MQTT、定位、报表和导入压测。
- PostgreSQL 备份、恢复、分区和保留策略。
- Redis 故障、Broker 故障、Worker 滚动更新和主备切换演练。
- 日志、指标、告警、值班手册和故障处理手册。
- 生产开源 Broker 选型验证。
- 如需迁移：清洗、映射、演练、核对、回滚和切换计划。
- 试点项目、用户培训、验收记录和发布回滚方案。

### 退出条件

- 容量满足已经书面确认的设备规模、峰值和延迟目标。
- 备份可实际恢复，不只验证“备份任务成功”。
- 高优先级安全问题关闭，密钥和凭据未进入代码、日志或前端。
- 生产监控能发现连接、积压、错误率和业务异常。
- 试点项目完成真实设备与真实用户验收。
- 发布和回滚均完成演练。

## 12. 持续并行工作

### 12.1 质量

- 领域单元测试：权限求值、幂等、状态机、告警和盘点。
- 集成测试：PostgreSQL、Redis、Mosquitto、对象存储。
- 契约测试：OpenAPI 和每个 MQTT 协议版本。
- 端到端测试：Root、超级管理员、两个租户、每租户两个项目、多角色，以及跨租户/跨项目拒绝。
- 数据库迁移测试：空库升级和已有版本升级。

### 12.2 安全

- 依赖更新、秘密扫描、最小权限和安全评审持续执行。
- 每个新模块都检查 API、WebSocket、文件、导出和批量接口。
- 高风险设备命令采用单独威胁模型。

### 12.3 文档

- 需求、架构、权限、协议、OpenAPI、数据库迁移和运维文档随代码更新。
- 重大技术取舍使用 ADR 记录背景、选项和后果。
- 用户提供的新协议样例进入脱敏测试资产，不只保存在聊天记录。

## 13. 优先级与变更控制

首条优先业务链为：

```text
登录与租户/项目授权
→ 资产/网关/信标主数据
→ 真实 MQTT 上行
→ 当前状态与实时页面
→ 告警或定位中的一个真实场景
```

任何新增需求先判断：

1. 是否属于已确认 V1 范围。
2. 是否改变权限、租户/项目隔离或数据保留。
3. 是否要求新的设备协议或外部服务。
4. 是否影响已经发布的数据或 API 契约。
5. 是否需要调整当前阶段退出条件。

影响范围、数据模型或上线风险的变更应进入需求文档并重新确认，而不是直接变成隐藏实现。

## 14. 当前关键依赖

在以下资料到位前，对应事项保持“未开始/受阻”，不得用假数据替代：

- MQTT Topic、真实报文和字段字典。
- 下行命令与 ACK（如果需要设备控制）。
- 设备规模、上报频率和保留期。
- 定位数据、坐标和精度要求。
- 旧数据迁移决策与样本。
- 生产开源 Broker、对象存储和部署 SLA。
